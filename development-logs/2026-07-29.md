## 🏗️ 架构设计

### 1. 架构模式选择

#### 决策过程

**选项 A：单模块架构**
- 优点：结构简单，使用方便，依赖管理简单
- 缺点：耦合度高，不利于团队协作，发布体积大

**选项 B：多模块架构**
- 优点：模块解耦，独立发布，便于团队协作，按需依赖
- 缺点：结构复杂，维护成本高

**最终选择：多模块架构**

#### 理由

1. **功能独立性** - 不同网络协议可以独立开发和测试
2. **按需依赖** - 应用可以选择性集成需要的模块，减小 APK 体积
3. **团队协作** - 不同开发者可以并行开发不同模块
4. **版本管理** - 各模块可以独立发版，互不影响

### 2. 模块划分设计

#### 最终模块结构

```
NetworkDemo/
├── app/                          # 示例应用模块
├── build-logic/                  # Gradle 约定插件
│   └── convention/               # 插件实现
├── network-core/                 # 核心基础设施模块
├── network-http/                 # HTTP/HTTPS 模块（待实现）
├── network-socket/               # Socket 模块（待实现）
├── network-monitor/              # 网络监测模块
└── network-download/             # 文件下载模块（待实现）
```

#### 模块职责

| 模块 | 职责 | 依赖 |
|------|------|------|
| **network-core** | 异常体系、日志系统、线程池管理、Flow 工具、数据模型 | 无（基础模块） |
| **network-monitor** | 网络状态监听、网络类型判断 | network-core |
| **network-http** | HTTP/HTTPS 请求封装 | network-core |
| **network-socket** | TCP Socket 和 WebSocket | network-core |
| **network-download** | 文件下载、断点续传 | network-core, network-http |

### 3. 技术选型

#### 核心技术栈

| 技术 | 版本 | 选择理由 |
|------|------|---------|
| **Kotlin** | 2.2.10 | 现代化、空安全、协程支持 |
| **Gradle** | 9.4.1 | 最新稳定版 |
| **Android AGP** | 9.2.1 | 与 Gradle 9.4 兼容 |
| **Jetpack Compose** | BOM 2025.04.01 | 现代化 UI 框架 |
| **Coroutines** | 1.7.3 | 结构化并发、Flow 支持 |
| **OkHttp** | 4.12.0 | 主流 HTTP 客户端（计划） |

#### 为何选择 Kotlin Coroutines + Flow？

1. **响应式编程** - Flow 提供声明式的数据流处理
2. **结构化并发** - 协程自动管理生命周期，避免内存泄漏
3. **类型安全** - 编译时检查，减少运行时错误
4. **易用性** - 简洁的 API，减少回调地狱
5. **生态完善** - Android 官方推荐，集成度高

### 阶段二：network-core 核心模块（1小时）

#### 2.1 异常体系设计

**设计思路：**

```
Throwable (Android 系统类)
    └─ RuntimeException (Kotlin 标准异常)
        └─ NetworkException (网络库基础异常)
            ├─ HttpException (HTTP 相关异常)
            ├─ SocketException (Socket 相关异常)
            └─ DownloadException (下载相关异常)
```

**关键代码：**

```kotlin
open class NetworkException(
    val code: Int,
    override val message: String,
    override val cause: Throwable? = null
) : RuntimeException(message, cause)
```

**遇到的坑：**

1. **类型冲突错误**
   - 问题：`cause` 与 `Throwable` 父类同名，需要 `override` 修饰符
   - 解决：添加 `override val cause: Throwable? = null`

#### 2.2 日志系统设计

**设计模式：** 接口 + 默认实现

**接口定义：**

```kotlin
interface Logger {
    fun v(tag: String, message: String)
    fun d(tag: String, message: String)
    fun i(tag: String, message: String)
    fun w(tag: String, message: String)
    fun e(tag: String, message: String, throwable: Throwable? = null)
}
```

**默认实现：** 基于 Android Logcat

**扩展性：** 用户可以替换为 Timber、Timber2、Log4a 等

#### 2.3 线程池管理

**设计思路：** 协程调度器 + 作用域管理

```kotlin
interface DispatcherProvider {
    val IO: CoroutineDispatcher
    val Main: CoroutineDispatcher
    val Default: CoroutineDispatcher
}
```

**优势：**
- 自动切换线程，避免手动切换
- 结构化并发，自动取消子协程
- 便于测试，可以替换测试调度器

#### 2.4 Flow 工具类

**关键功能：**

1. **FlowBuilder** - 回调转 Flow
```kotlin
inline fun <T> callbackFlow(
    crossinline register: (callback: (T) -> Unit) -> Unit,
    crossinline unregister: (callback: (T) -> Unit) -> Unit
): Flow<T>
```

2. **FlowExtensions** - Flow 扩展操作符
   - `catchAndLog()` - 捕获异常并记录日志
   - `retryWithDelay()` - 延迟重试
   - `retryWithExponentialBackoff()` - 指数退避重试
   - `throttleFirst()` - 节流（窗口内只发射第一个值）
   - `debounceByTime()` - 去抖动（无新值才发射）
   - `batch()` - 批量处理

**遇到的坑：**

1. **Duration API 已废弃**
   - 问题：`Duration.milliseconds()` 在 Kotlin 1.6+ 已移除
   - 解决：使用 `1000.milliseconds` 或导入 `kotlin.time.Duration.Companion.milliseconds`

#### 2.5 数据模型设计

**设计原则：** 使用密封类（sealed class）和枚举

**核心模型：**

```kotlin
// 网络请求结果
sealed class NetworkResult<out T> {
    data class Success<T>(val data: T) : NetworkResult<T>()
    data class Error<T>(val exception: Throwable) : NetworkResult<T>()
    data class Loading<T>(val progress: Int = 0) : NetworkResult<T>()
}

// 网络状态
sealed class NetworkState {
    object Idle : NetworkState()
    object Connecting : NetworkState()
    data class Connected(val type: NetworkType) : NetworkState()
    data class Disconnected(val reason: String?) : NetworkState()
}

// 下载进度
data class DownloadProgress(
    val url: String,
    val fileName: String,
    val currentBytes: Long,
    val totalBytes: Long,
    val progress: Int,        // 0-100
    val speed: Long,          // 字节/秒
    val status: DownloadStatus
)
```

**遇到的坑：**

1. **泛型型变冲突**
   - 问题：`fun getOrDefault(default: T): T` 中 T 在 `in` 位置，但 `NetworkResult<out T>` 声明为协变
   - 解决：使用 `@UnsafeVariance` 注解

### 阶段三：network-monitor 网络监测模块（2小时）

#### 3.1 核心设计

**设计思路：** StateFlow 管理状态，自动推送更新

**核心接口：**

```kotlin
interface NetworkMonitor {
    // 网络状态（StateFlow）
    val networkState: StateFlow<NetworkState>

    // 获取当前状态
    fun getCurrentState(): NetworkState

    // 检查连接状态
    fun isConnected(): Boolean

    // 检查可用性
    fun isAvailable(): Boolean

    // 监听网络信息
    fun observeNetworkInfo(): Flow<NetworkInfo>

    // 监听可用性
    fun observeAvailability(): Flow<Boolean>
}
```

#### 3.2 Android 版本适配

**挑战：** 需要兼容 Android 5.0 (API 21) - Android 15 (API 36)

**版本分层策略：**

```
Android 5.0-5.1 (API 21-22)
├─ 使用 NetworkCallback 注册监听
├─ 使用 NetworkInfo 判断状态
└─ 根据 subtype 判断网络类型

Android 6.0-9.0 (API 23-28)
├─ 使用 NetworkCapabilities
├─ 使用 getActiveNetwork()
└─ 根据带宽估算网络类型

Android 10+ (API 29+)
├─ 使用 NetworkCapabilities
├─ 精确判断网络类型
└─ 支持 5G 检测

Android 11+ (API 30+)
└─ 反射获取 NET_CAPABILITY_MMSECURE
```

**关键实现：**

```kotlin
private fun getNetworkType(capabilities: NetworkCapabilities): NetworkType {
    // WiFi
    if (capabilities.hasTransport(NetworkCapabilities.TRANSPORT_WIFI)) {
        return NetworkType.WIFI
    }

    // 移动网络
    if (capabilities.hasTransport(NetworkCapabilities.TRANSPORT_CELLULAR)) {
        return getCellularNetworkType(capabilities)
    }

    // 以太网
    if (capabilities.hasTransport(NetworkCapabilities.TRANSPORT_ETHERNET)) {
        return NetworkType.ETHERNET
    }

    return NetworkType.UNKNOWN
}
```

#### 3.3 5G 网络检测

**问题：** `NET_CAPABILITY_MMSECURE` 是 Android 11 (API 30) 才引入的常量

**解决方案：** 反射 + 缓存

```kotlin
// 缓存 5G 能力常量
private var netCapabilityMmsecure: Int = -1

private fun init5GCapability() {
    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.R) {
        try {
            // 通过反射获取常量
            val field = NetworkCapabilities::class.java
                .getDeclaredField("NET_CAPABILITY_MMSECURE")
            netCapabilityMmsecure = field.getInt(null)
        } catch (e: Exception) {
            // 反射失败，使用带宽估算
            netCapabilityMmsecure = -1
        }
    }
}
```

**遇到的坑：**

1. **编译错误：Unresolved reference**
   - 问题：`NET_CAPABILITY_MMSECURE` 在低版本编译器中不存在
   - 解决：使用反射动态获取

2. **Lint 警告：WrongConstant**
   - 问题：Lint 无法识别反射获取的常量值
   - 解决：添加 `@SuppressLint("WrongConstant")` 注解

#### 3.4 类型命名冲突

**问题：** Android 的 `NetworkInfo` 和自定义的 `NetworkInfo` 同名

**解决方案：**
```kotlin
// 导入 Android 的 NetworkInfo 时明确指定
import android.net.NetworkInfo as AndroidNetworkInfo

// 或在代码中明确指定类型
val legacyInfo: android.net.NetworkInfo? = cm.activeNetworkInfo
```

## 🎓 学习要点

### 1. Gradle 约定插件

**什么是约定插件？**

Gradle Convention Plugins 是 Gradle 6.0+ 引入的机制，用于将通用的构建逻辑封装成可重用的插件。

**优势：**
- 代码复用：多个模块共享相同的构建逻辑
- 类型安全：Kotlin DSL 提供编译时检查
- 易于维护：集中管理构建逻辑

**实现步骤：**

1. 创建 `build-logic/convention/src/main/kotlin/`
2. 编写插件逻辑（如 `AndroidCommon.kt`）
3. 在其他模块中使用 `alias(libs.plugins.xxx)`

### 2. Kotlin 泛型型变

**协变（out T）：** T 只能作为输出（返回类型）
```kotlin
sealed class NetworkResult<out T>
```

**逆变（in T）：** T 只能作为输入（参数类型）
```kotlin
interface Consumer<in T> {
    fun consume(item: T)
}
```

**@UnsafeVariance：** 告诉编译器"我知道风险，但保证安全"
```kotlin
fun getOrDefault(default: @UnsafeVariance T): T
```

### 3. Android 反射

**何时使用反射？**
- 兼容不同 Android 版本的 API
- 访问私有 API（谨慎使用）
- 动态加载类和方法

**性能考虑：**
- 反射调用比直接调用慢 10-100 倍
- 建议缓存反射结果
- 避免在热路径中使用

### 4. Kotlin Coroutines + Flow

**StateFlow vs Flow：**

| 特性 | StateFlow | Flow |
|------|-----------|------|
| 发射最新值 | ✅ 自动重发 | ❌ 需要重新订阅 |
| 缓存机制 | ✅ 自动缓存 | ❌ 无缓存 |
| 状态管理 | ✅ 适合状态 | ❌ 适合事件 |
| 订阅行为 | 始终发射最新值 | 从头开始发射 |

**Flow 操作符：**
- `map()` - 转换数据
- `filter()` - 过滤数据
- `debounce()` - 去抖动
- `throttleFirst()` - 节流
- `retryWhen()` - 条件重试
- `catch()` - 异常捕获
- `onEach()` - 副作用操作

### 5. Android 版本适配

**版本判断方法：**

```kotlin
// 方法 1：Build.VERSION.SDK_INT

// 方法 2：@RequiresApi

    val field = NetworkCapabilities::class.java.getDeclaredField("XXX")
    // 使用反射获取新 API

    // 降级方案
}
```

**废弃 API 处理：**
```kotlin

val networkInfo = cm.activeNetworkInfo
```

### 1. 架构设计

- **分层清晰**：API 层 → 业务层 → 核心层
- **单一职责**：每个模块只负责一个功能

## 🔍 问题排查

### 1. Gradle 构建失败

**常见原因：**
- JDK 版本不匹配
- 依赖版本冲突
- Gradle 缓存损坏

**解决方法：**
```bash
# 清理 Gradle 缓存
./gradlew clean

# 重新下载依赖
./gradlew --refresh-dependencies

# 检查依赖树
./gradlew app:dependencies
```

### 2. AndroidManifest 合并冲突

**常见原因：**
- 多个模块声明了相同的权限
- minSdk 版本不一致

**解决方法：**
```xml
<!-- 使用 tools:replace 强制覆盖 -->
<uses-permission
    android:name="android.permission.INTERNET"
    tools:replace="android:required" />
```

### 3. Lint 警告

**常见原因：**
- 使用了废弃的 API
- 泛型类型不安全

**解决方法：**
```kotlin
// 方式 1：注解抑制
@Suppress("DEPRECATION")

// 方式 2：全局配置（build.gradle.kts）
android {
    lint {
        disable += "DeprecatedScopeUsed"
    }
}
```

## 📚 技术专题：Kotlin 协程 Scope 深度解析

### 核心概念：什么是 Scope？

**Scope（作用域）** 定义了协程的**生命周期边界**：

```
Scope = 协程的生命周期管理器
    ↓
决定：
    • 何时启动协程
    • 何时取消协程
    • 在哪个线程执行
    • 如何处理异常
```

---

### 所有 Scope 分类

#### 第一类：全局作用域

| Scope | 生命周期 | 内存泄漏风险 | 使用场景 |
|-------|---------|------------|---------|
| **GlobalScope** | 应用进程级别 | ⚠️ **极高** | 几乎不用 |

```kotlin
// ❌ 不推荐：GlobalScope（生命周期不可控）
GlobalScope.launch {
    // 应用进程死亡时才结束
    // 容易导致内存泄漏
}
```

**为什么不推荐？**
- ❌ 无法手动取消
- ❌ 生命周期不可控
- ❌ 容易内存泄漏

---

#### 第二类：Android 组件作用域

##### 1. MainScope()

```kotlin
// ✅ 手动管理的顶级作用域
class MyApplication : Application() {
    private val mainScope = MainScope()

    override fun onCreate() {
        super.onCreate()
        mainScope.launch {
            // 在主线程执行
        }
    }

    override fun onTerminate() {
        super.onTerminate()
        mainScope.cancel()  // ← 必须手动取消！
    }
}
```

**特点：**
- ✅ 在主线程执行
- ⚠️ 需要手动取消
- ✅ 适合 Application 级别

---

##### 2. lifecycleScope

```kotlin
// ✅ Activity/Fragment 生命周期绑定
class MainActivity : AppCompatActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        // 自动绑定 Activity 生命周期
        lifecycleScope.launch {
            // Activity 销毁时自动取消
            delay(1000)
            textView.text = "Hello"
        }

        // 在 IO 线程执行
        lifecycleScope.launch(Dispatchers.IO) {
            val data = fetchFromNetwork()
            withContext(Dispatchers.Main) {
                textView.text = data
            }
        }
    }
}
```

**特点：**
- ✅ 自动绑定 Activity/Fragment 生命周期
- ✅ Activity 销毁时自动取消
- ✅ 防止内存泄漏
- ✅ 最常用

**依赖：**
```kotlin
implementation("androidx.lifecycle:lifecycle-runtime-ktx:2.8.7")
```

---

##### 3. viewModelScope

```kotlin
// ✅ ViewModel 生命周期绑定
class MyViewModel : ViewModel() {

    fun loadData() {
        viewModelScope.launch {
            // ViewModel 清除时自动取消
            val data = repository.fetchData()
            _data.value = data
        }
    }

    // 自定义异常处理
    fun loadDataWithCatch() {
        viewModelScope.launch {
            try {
                val data = repository.fetchData()
                _data.value = data
            } catch (e: Exception) {
                _error.value = e.message
            }
        }
    }
}
```

**特点：**
- ✅ 自动绑定 ViewModel 生命周期
- ✅ ViewModel 清除时自动取消
- ✅ 最佳实践（配合 ViewModel）
- ✅ 自动处理屏幕旋转

**依赖：**
```kotlin
implementation("androidx.lifecycle:lifecycle-viewmodel-ktx:2.8.7")
```

---

##### 4. rememberCoroutineScope (Compose)

```kotlin
// ✅ Compose 生命周期绑定
@Composable
fun MyScreen() {
    val scope = rememberCoroutineScope()

    Button(onClick = {
        scope.launch {
            // Composable 销毁时自动取消
            delay(1000)
            // 执行操作
        }
    }) {
        Text("Click me")
    }
}
```

**特点：**
- ✅ Compose 专用
- ✅ Composable 销毁时自动取消
- ✅ 在事件处理器中使用（如 onClick）

**依赖：**
```kotlin
implementation("androidx.compose.runtime:runtime:1.7.8")
```

---

#### 第三类：协程构建器作用域

##### 5. runBlocking {}

```kotlin
// ⚠️ 阻塞当前线程（测试用）
fun main() = runBlocking {
    println("Start")
    delay(1000)  // ← 阻塞主线程 1 秒
    println("End")
}
```

**特点：**
- ⚠️ **阻塞当前线程**
- ⚠️ 不适合 Android UI 线程
- ✅ 适合单元测试
- ✅ 适合 main 函数

**使用场景：**
```kotlin
// ✅ 单元测试
@Test
fun testNetworkRequest() = runBlocking {
    val result = repository.fetchData()
    assertEquals("expected", result)
}

// ✅ main 函数
fun main() = runBlocking {
    val data = fetchData()
    println(data)
}
```

---

##### 6. coroutineScope {}

```kotlin
// ✅ 挂起函数作用域
suspend fun fetchAllData(): List<Data> = coroutineScope {
    // 并发执行多个请求
    val deferred1 = async { fetchFromApi1() }
    val deferred2 = async { fetchFromApi2() }
    val deferred3 = async { fetchFromApi3() }

    // 等待所有请求完成
    deferred1.await() + deferred2.await() + deferred3.await()
}
```

**特点：**
- ✅ 挂起函数内部使用
- ✅ 子协程全部完成后才返回
- ✅ 异常会取消其他子协程
- ✅ 结构化并发

---

##### 7. supervisorScope {}

```kotlin
// ✅ 独立异常处理
suspend fun loadAllData() = supervisorScope {
    val job1 = launch {
        // 子协程1
        throw Exception("Error in job1")  // ← 失败
    }

    val job2 = launch {
        // 子协程2
        delay(1000)
        println("Job2 completed")  // ← 继续执行
    }

    job1.join()
    job2.join()
}
```

**特点：**
- ✅ 子协程异常互不影响
- ✅ 适合独立任务
- ✅ 一个失败不影响其他

---

#### 第四类：自定义作用域

##### 8. CoroutineScope()

```kotlin
// ✅ 完全自定义
class MyRepository {
    private val scope = CoroutineScope(Dispatchers.IO + SupervisorJob())

    fun loadData() {
        scope.launch {
            // 在 IO 线程执行
        }
    }

    fun clear() {
        scope.cancel()  // ← 必须手动取消！
    }
}
```

**特点：**
- ✅ 完全自定义
- ⚠️ 需要手动管理生命周期
- ✅ 适合自定义组件

### 常见错误

#### 错误一：在 Activity 中使用 GlobalScope
```kotlin
// ❌ 错误
class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        GlobalScope.launch {  // ← Activity 销毁后不会取消
            val data = fetchData()
            textView.text = data  // ← Activity 已销毁，崩溃！
        }
    }
}
```

---

#### 错误二：在 ViewModel 中使用 lifecycleScope
```kotlin
// ❌ 错误
class MyViewModel : ViewModel() {
    fun loadData() {
        // lifecycleScope 需要 LifecycleOwner
        lifecycleScope.launch {  // ← 编译错误！
            // ...
        }
    }
}
```

---

#### 错误三：在 Composable 中使用 GlobalScope
```kotlin
// ❌ 错误
@Composable
fun MyScreen() {
    GlobalScope.launch {  // ← Composable 销毁后不会取消
        // ...
    }
}
```

---

### 核心原则

```
1. 永远不要用 GlobalScope
2. 优先使用结构化并发
3. 选择生命周期最接近的 Scope
4. 让协程自动取消，不要手动管理
```

---

### 选择指南

```
Activity/Fragment → lifecycleScope
ViewModel         → viewModelScope
Compose           → rememberCoroutineScope
Application       → MainScope() (手动取消)
Repository        → CoroutineScope(Dispatchers.IO)
挂起函数          → coroutineScope
测试              → runBlocking
```
